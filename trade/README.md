# 日本株スイングトレード スクリーニングシステム

テクニカル指標だけを使い、**期待値（EV）の高いスイングトレード候補**を日本株
約3,700銘柄から抽出するシステムです。ランキングを出すだけでなく、そのランキングが
本当に機能するのかを **ウォークフォワード検証** で測り、機能していなければ
そう表示します。

---

## 1. 設計の考え方

### 「期待値が高い」を測定可能な形にする

「良さそうな銘柄」を並べるだけのスクリーナーは検証できません。そこで本システムは、
先に**売買ルールを完全に固定**し、そのルールで売買したときの成績を予測対象にします。

| 項目 | 既定値 | 理由 |
|---|---|---|
| エントリー | シグナル発生日の**翌営業日の寄付** | シグナル当日の終値では約定できない。ここを終値にすると先読みになる |
| 損切り | エントリー − ATR(14) × 1.5 | この幅を **1R**（リスク単位）と定義 |
| 利益確定 | エントリー + ATR(14) × 3.0 | リスクリワード 1:2 |
| 時間切れ | 15営業日後の終値 | どちらにも当たらなければ手仕舞う |
| 往復コスト | 0.15% | 手数料・スプレッド・スリッページ |

結果は **R倍数** で記録します。400円の銘柄と9,000円の銘柄を同じ土俵で比較できる
のはこの正規化のおかげで、1本のランキングが意味を持つ前提になっています。

期待値 EV = 平均R = 勝率 × 平均利益R − 負率 × 平均損失R。

### 悲観側に倒す2つの実装

- **ギャップ**：損切り注文は約定価格を保証しません。窓を開けて損切り水準を
  下抜けた場合、約定は**寄値**であって損切り価格ではありません。これを無視すると
  測定される期待値は必ず甘くなります。
- **同一日の両建て**：日足では高値と安値のどちらが先に来たか判別できません。
  1本の足が損切りと目標の両方に触れた場合、本システムは**常に損切りを採用**します。

### スコアの作り方（3段階）

1. **正規化** — 各ファクターを「高いほど良い」向きに揃え、外れ値を丸めた上で
   **その日の全銘柄の中で** 偏差値化します。横断面で標準化することで、スコアは
   「今日はどの銘柄が良いか」を答えるようになり、相場全体の水準変化に影響されません。

2. **重み付け** — 各ファクターの **IC（情報係数）**、すなわち日ごとに測った
   ファクターと実現Rの順位相関の平均から重みを決めます。重みは縮小推定して
   0で下限を切るため、ノイズと区別がつかないファクターは**自動的に不採用**に
   なります。ただし符号の反転は許しません。方向はファクター定義に書かれた事前知識で、
   1つの学習期間がそれを覆すことは認めない、という設計です。

3. **較正** — 合成スコアを実際の期待値Rに変換します。学習データをスコア順に
   10分割し、各グループが実際に何Rを生んだかを測って対応表を作ります。この段階が
   あるため、出力は「+0.18R」という単位のある数値になり、意味不明のスコアには
   なりません。

### 検証：スコアは本当に効いているのか

学習に使ったデータで測れば、どんなファクターの組み合わせも良く見えます。重みは
そう見えるように選ばれたのだから当然です。そこで本システムは学習期間ごとに
モデルを作り直し、**その後の期間だけ**で採点します。

学習期間と検証期間の間には **エンバーゴ（空白期間）** を置きます。これは見た目
以上に重要で、学習期間最終日に発生したトレードは最大15営業日ポジションを持ち続け
ます。空白を置かないとその決済が検証期間に食い込み、「アウトオブサンプル」が
一部インサンプルになってしまいます。

**最重要の出力は、検証期間におけるスコア10分位別の実現Rです。** この表が右肩上がり
でなければ、資産曲線がどれほど綺麗でもスコアは主張どおりのものを測っていません。

そして**実運用のEV較正には、この検証期間で得られたスコアと結果の組**を使います。
インサンプルで較正すると「そう再現するよう当てはめた期待値」を報告することになり、
確実に楽観的すぎるからです。

### ハードフィルタ（スコアリング以前に除外）

流動性の低い銘柄は、実際には約定できないリターンでバックテストを支配します。
本システムで最も重要な防御がここです。

- 25日平均売買代金 **3億円以上**
- 株価 300〜30,000円（1単元が現実的な価格帯）
- ATR% が 1.0%〜12.0%（値動きが小さすぎる／荒すぎる銘柄を除外）
- 260営業日以上の株価履歴

> **なぜ対TOPIX相対強度を単純比で入れていないか**
> 開発中、対TOPIX相対強度のICが60日騰落率と小数点以下4桁まで一致しました。
> ベンチマークはその日の全銘柄で共通なので、それで割るのは日ごとの単調変換に
> すぎず、**横断面の情報を何も足していなかった**ためです。現在は代わりに、
> 銘柄ごとに変化する「残差モメンタム」と「同業種内相対強度」を使っています。

## 2.5 データ品質 — 精度を決める最大の要因

モデルをいくら精緻にしても、入力データに以下のバイアスが残っていれば結果は
信用できません。実測して分かったことを、影響の大きい順に並べます。

### (1) 重なり合うラベルによる有意性の過大評価【最大の問題・修正済み】

保有期間15営業日のトレードを毎日評価しているため、隣り合う日のICは
**結果ウィンドウの14/15を共有**しています。それを独立と見なして日数の
平方根でt値を計算すると、有意性が大幅に水増しされます。実測した日次ICの
自己相関は **0.64〜0.84**、Newey-West補正後のt値は素朴なt値の
**0.37〜0.53倍** でした。

| ファクター | IC | 素朴なt | NW補正後t | 自己相関 |
|---|---|---|---|---|
| pullback_atr | +0.046 | +18.52 | **+9.05** | 0.73 |
| mom_120_20 | +0.020 | +10.29 | **+3.75** | 0.78 |
| sma75_slope | +0.012 | +5.94 | **+2.10** | 0.80 |
| vol_ratio25 | +0.014 | +6.27 | **+5.51** | 0.06 |

`sma75_slope` は素朴なt値では十分に有意に見えますが、補正すると
**多重検定の閾値（16ファクターのBonferroni補正で |t| ≥ 2.96）を下回り**、
不採用になります。修正前は重みの8.4%を持っていました。

`vol_ratio25` は1日で完結する指標なので自己相関が0.06しかなく、t値がほとんど
下がりません。補正が一律の縮小ではなく、重なりの有無を正しく区別している
ことの確認になっています。

### (2) 値幅制限（ストップ高／安）【修正済み】

寄らずのストップ高では買えません。にもかかわらず「寄値で約定した」と
仮定すると、**ブレイクアウト銘柄という最も自信のある場面でこそ**
存在しない約定を計上することになります。ストップ安で固まった日も同様に
損切りできません。JPX公表の制限値幅テーブルを実装し、

- エントリー日が寄らずのストップ高 → **シグナルごと除外**（そもそも取引が成立していない）
- 損切り日が寄らずのストップ安 → **翌日の寄値で約定**（−1Rでは済まない）

としています。`respect_price_limits=False` で旧挙動に戻せます。

### (3) サバイバーシップバイアス【日本株では通説が当てはまりません】

同梱の銘柄リストは**現在上場している銘柄のみ**です。JPXの上場廃止銘柄一覧を
スクレイピングして実測したところ、バックテスト期間（2019/08〜2026/08）に
**617銘柄が上場廃止**されており、当時の母集団の約14%が欠けていました。

ただし内訳が重要です。

| 分類 | 件数 | 割合 |
|---|---|---|
| M&A・TOB・完全子会社化・株式併合による締出し | 592 | **96.0%** |
| 経営不振・上場維持基準への不適合（真の失敗） | 17 | 2.8% |
| その他 | 8 | 1.3% |

米国株で言われる「消えた敗者が欠けているのでバックテストが過大評価になる」
という定説は、**日本株には素直に当てはまりません**。欠けている銘柄の大半は
TOBプレミアムを付けて退場した銘柄です。買い戦略にとってはむしろ
右側の裾を過小評価している可能性があります。

**結論として、サバイバーシップバイアスの是正は最優先ではありません。**
それでも正確性のために対応できるよう、無料でスクレイピングできる仕組みを
用意しています。

```bash
python -m screener.cli delisted --refresh
```

### (4) 配当調整はテクニカル分析を歪めます

yfinance の `auto_adjust=True` は分割だけでなく**配当も**遡って調整します。
その結果、過去の株価が実際に取引された価格から下方にずれ、「52週高値」や
「25日移動平均」が、当時トレーダーが見ていた水準とは別物になります。
テクニカル分析では **分割調整のみ・配当調整なし** が正解です。
J-Quants は生の四本値と分割調整係数を別々に返すため、ここを正しく扱えます。

## 2.6 推奨データソース：J-Quants API

JPX（日本取引所グループ）自身が提供する個人向けAPIです。日本株の
テクニカル分析用データとしては、価格・品質のバランスで他を圧倒しています。

| プラン | 月額 | 履歴 | 遅延 |
|---|---|---|---|
| Free | ¥0 | 2年 | 12週間 |
| Light | ¥1,650 | 5年 | なし |
| Standard | ¥3,300 | 10年 | なし |
| Premium | ¥16,500 | 2008/05/07〜全期間 | なし |

**本システムにとっての決定的な利点は3つです。**

1. **`/listed/info` が `date` パラメータを受け付ける** — 過去の任意時点の
   上場銘柄一覧を取得できます。サバイバーシップバイアスを原理的に解消できる
   唯一の手段です（Premiumなら2008年まで遡れます）。
2. **`AdjustmentFactor` と生の四本値が別々に取得できる** — 上記(4)の
   配当調整問題を回避できます。
3. **`UpperLimit` / `LowerLimit`** — ストップ高／安のフラグが日次で付いており、
   上記(2)の判定を推定ではなく実データで行えます。

7年分のスイングトレード検証には **Standard（¥3,300/月・10年）** が下限として
妥当です。Lightの5年では、ウォークフォワードの学習期間を十分に取ると
検証期間がほとんど残りません。

```bash
export JQUANTS_MAIL_ADDRESS="you@example.com"
export JQUANTS_PASSWORD="..."
python -m screener.cli update --provider jquants --years 7
```

### 他の選択肢

| ソース | 費用 | 評価 |
|---|---|---|
| **J-Quants** | ¥0〜16,500/月 | **推奨。** JPX公式。上記3点を満たす唯一の現実的な選択肢 |
| yfinance | 無料 | 手軽だが配当調整が混入し、上場廃止銘柄がなく、レート制限が厳しい。試用向け |
| stooq | 無料 | CSVで手軽。ただしBot対策のJSチャレンジが入ることがあり、調整履歴の品質が不明 |
| kabu STATION API | 証券口座 | リアルタイム・発注まで可能。ヒストリカルには不向き |
| Refinitiv / Bloomberg | 数十万円〜/月 | 個人の技術分析用途には過剰 |

## 4. 使い方

```bash
# 1. 銘柄リストを最新化（JPXの公開Excelから取得。同梱済みなので初回は任意）
python -m screener.cli universe --refresh

# 2. 株価を取得してローカルキャッシュに保存（7年分。初回は時間がかかります）
python -m screener.cli update --provider yfinance --years 7

# 3. ウォークフォワード検証＋実運用モデルの学習
python -m screener.cli backtest

# 4. 当日のスクリーニング＋ダッシュボード用JSONの出力
python -m screener.cli screen --equity 3000000 --risk 0.01

# 5. ダッシュボードを表示
python -m screener.cli serve      # http://localhost:8000
```

`run` は 2〜4 をまとめて実行します（日次バッチ向け）。

```bash
python -m screener.cli run --provider yfinance
```

### ネットワークが使えない環境で試す

合成データで全機能を動かせます。**架空の株価**であり、実在銘柄の値動きでは
ありません。ダッシュボードにもその旨のバナーが出ます。

```bash
python -m screener.cli update  --provider synthetic --years 8 --limit 400 --rebuild
python -m screener.cli backtest --provider synthetic --limit 400
python -m screener.cli screen   --provider synthetic --limit 400
python -m screener.cli serve
```

### 主なオプション

| オプション | 説明 |
|---|---|
| `--provider` | `jquants`（推奨） / `yfinance`（既定） / `stooq` / `synthetic` |
| `--limit N` | 先頭N銘柄だけ使う（試行を速くする） |
| `--markets` | `prime` `standard` `growth` から選択 |
| `--min-turnover` | 最低売買代金の上書き（円） |
| `--equity` `--risk` | 運用資金と1トレードのリスク率 |
| `--csv PATH` | ランキングをCSVでも書き出す |

## 5. ダッシュボード

`screen` が `dashboard/data/*.json` を書き出し、静的ページがそれを表示します。
ビルド手順もサーバーサイドの処理もありません。

- **候補銘柄** — 相場環境、スコア上位、損切り・目標・株数。運用資金やリスク率を
  変えると**その場で全行が再計算**されます。行をクリックすると日足チャートと
  スコアの内訳（どのファクターが何ポイント寄与したか）が開きます。
- **検証結果** — 10分位別の実現期待値、資産曲線、ファクター別IC、分割の内訳。
- **ファクター定義** — 売買ルール、フィルタ条件、全ファクターの定義と採用重み。

検証が不合格のとき（単調性 < 0.6）と、当日の候補が全て期待値マイナスのときは、
画面上部に警告が出ます。**順位が高いことと、買うべきであることは別**だからです。

## 8. 精度を上げるための残作業（優先順）

実測に基づく優先順位です。上から順に費用対効果が高い順に並べています。

| # | 項目 | 状態 | 効果 |
|---|---|---|---|
| 1 | 重なりラベルのt値補正（Newey-West＋多重検定） | **実装済** | 採用ファクターが変わる。最大 |
| 2 | 値幅制限（ストップ高／安）の反映 | **実装済** | 最も自信のある場面の過大評価を除去 |
| 3 | J-Quantsへの移行（配当調整の除去） | **provider実装済**（要契約） | 全指標の水準が正しくなる |
| 4 | ポイントインタイム母集団 | **スクレイパ実装済**（結合は未） | 日本株では効果は限定的（上記2.5(3)） |
| 5 | 決算発表日の除外 | 未 | 決算跨ぎは別分布。J-Quants Freeで取得可 |
| 6 | 業種・サイズ・βの中立化 | 未 | スコアが「業種賭け」になるのを防ぐ |
| 7 | 売買代金に対する建玉比率の制限とマーケットインパクト | 未 | 資金量が増えたときの現実性 |
| 8 | 呼値（ティックサイズ）への丸め | 未 | 影響は小さい |
| 9 | 非線形モデル（勾配ブースティング等）への差し替え | 未 | 線形IC重みの上限を超えるなら |

**5〜9より先に3を済ませてください。** モデルを高度化しても、入力が
配当調整済みの価格である限り、指標が測っているものが当時のチャートと
一致しません。

## 9. 制約と注意

- **合成データでの成績には意味がありません。** 合成データにはテクニカルで
  取れる優位性を埋め込んでいないため、検証は「単調性 +0.5、期待値ほぼ0」と
  出ます。これは配管が正しく動き、**過剰適合を検出できている**ことの確認であって、
  実データでの優位性の証明ではありません。実データで判断してください。
- 対象は**買い（ロング）のみ**です。ベンチマークが75日線を下回る局面では
  ダッシュボードが警告を出します。
- 分割・併合は yfinance の調整済み株価に依存します。配当は考慮していません。
- 単元株は一律100株として計算しています。
- 本システムは投資助言ではありません。投資判断は自己責任で行ってください。
